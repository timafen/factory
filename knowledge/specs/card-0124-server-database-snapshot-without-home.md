# Спецификация CARD-0124: снимок базы без зависимости от HOME

## Цель и влияние на владельца

Выпуск должен надёжно создавать SQLite-снимок даже когда systemd или посредник запускает его без переменной `HOME`. Для владельца это означает воспроизводимый выпуск без ручной настройки окружения; исходная рабочая база остаётся неизменной, а итоговый snapshot пригоден для восстановления.

## Технический подход и реальные файлы

Изменение уже реализовано и прошло Verify; этот этап только документирует точный дубль. В `ops/fx-factory-release` backup запускается через `as_user` с явным `-database` и `-backup`, пишет в рабочий каталог, очищает fallback-артефакты от имени того же пользователя, проверяет standalone SQLite, затем переносит snapshot и sidecar в staging и выставляет режим `600`. Базовый бинарник и свежесобранный fallback используют одинаковый контракт.

Реальный файл реализации: `ops/fx-factory-release`. Проверяемый тестовый контекст: subprocess-проверка форм backup-флагов без `HOME` и проверки standalone snapshot/неизменности источника из канонического Verify.

## Критерии приёмки

- Snapshot создаётся без унаследованного `HOME`.
- Backup выполняется владельцем базы, а готовый файл переносится в staging root-процессом.
- В staging отсутствуют WAL/SHM-побочные файлы; sidecar переносится вместе с snapshot.
- Путь `-database` и исходная база не подменяются; источник не изменяется.
- Проверка завершается кодом 0; новая реализация и UI не добавляются.

## Тест-план

- Целевая subprocess-проверка: четыре формы флагов backup при очищенном `HOME`.
- Проверить standalone SQLite, наличие ожидаемого sidecar и отсутствие WAL/SHM.
- Сравнить digest/содержимое исходной базы до и после snapshot.
- Выполнить обязательную синтаксическую проверку shell-файла.

## Риски и решения

- Удалённая каноническая ветка больше недоступна: фактический implementation commit найден в свежей `main`; карточка ссылается на полный SHA.
- Запуск под systemd без `HOME` мог ломать библиотеку домашнего каталога: backup выполняется через `as_user`, а окружение рабочего пользователя задаётся штатным release-контрактом.
- Перенос неполного snapshot мог оставить WAL/SHM: перед `mv` выполняется проверка standalone, а ошибка очищает staging.
