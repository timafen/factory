# Закрытие спецификации `area_busy()` как дубликата

## Цель и влияние на владельца

Эта работа не требует новой реализации: взаимное ожидание двух queued-работ,
пересекающихся по области файлов, уже устранено. Владелец получает
детерминированный выбор: работа на более поздней стадии конвейера продолжает
выполнение, а другая ожидает; при равных стадиях побеждает начатая раньше.
Работа со статусом `running` по-прежнему безусловно удерживает область.

Исправление уже внесено коммитом
`5f4e8eee02fa7845e857b6c549876648f10df836` («Замок областей решает споры сам:
старшая работа проходит, младшая ждёт (без взаимных ожиданий)»). По решению
владельца эта спецификация закрывает текущую задачу как дубликат; новые этапы
разработки, изменения продуктового кода и отдельная карточка не создаются.

## Технический подход и реальные файлы

Реализованная функция `area_busy()` в `pilot/pilot.py` получает область текущей
работы, сопоставляет её с областями остальных `running` и `queued` задач и
возвращает имя удерживающей работы либо пустую строку. Для queued-конфликта она
сравнивает `_area_rank`: больший номер стадии выигрывает, а равенство решается
более ранним `created_at`. Это исключает ситуацию, в которой обе queued-работы
видят друг друга и одновременно отказываются запускаться.

Покрытие в `pilot/test_pilot.py` содержит три сценария: безусловная блокировка
`running`, ровно один победитель при разных стадиях queued-работ и победа более
ранней queued-работы при одинаковой стадии.

## Последовательный план

1. Подтвердить, что исправляющий коммит и его два файла присутствуют в истории
   актуальной базы.
2. Выполнить только целевой класс `AreaLockArbitrationTests`.
3. Зафиксировать эту спецификацию как документальное закрытие-дубликат; не
   открывать новую реализацию и не создавать отдельную карточку согласно
   утверждённому ответу владельца.

## Критерии приёмки

- `running`-работа с пересекающейся областью всегда блокирует новую работу.
- Для двух пересекающихся queued-работ одна и только одна получает право пройти.
- При разных стадиях queued-работ проходит работа с более высоким номером
  стадии; при равных стадиях — начатая раньше.
- Новых изменений в `pilot/pilot.py` и `pilot/test_pilot.py` в рамках этой
  задачи нет: они уже содержатся в указанном исправляющем коммите.

## Тест-план

Запустить `python3 -m unittest pilot.test_pilot.AreaLockArbitrationTests`.
Ожидаемый результат — код завершения 0 и три успешных теста, подтверждающих
три правила арбитража.

## Риски и решения

- Риск повторно реализовать уже исправленное поведение и внести регрессию.
  Решение: задача закрыта как дубликат, продуктовый код не меняется.
- Риск неверно трактовать queued-конфликт как блокировку обоих участников.
  Решение: целевые тесты проверяют асимметричный результат для каждой стороны.
- Риск создать лишнюю карточку для исторической правки. Решение: владелец
  явно утвердил отсутствие отдельной карточки для этой дублирующей задачи.

## Карточка работы

Отдельная карточка не создаётся: в контексте отсутствует назначенная `Card:`,
а владелец утвердил закрытие текущей работы как дубликата уже выполненного
исправления без карточки.
