# Закрыть повтор исправления Claude health-probe как дубликат

## Цель и влияние на владельца

Закрыть текущую работу как `CLOSE / DUPLICATE`: ложный `unhealthy` при двух
одинаковых конкурентных Claude health-probe уже исправлен в CARD-0098 и доставлен
в `main` через PR #209 «конкурентные Claude health-probe ждут занятую команду».
Владелец не получает повторную реализацию, новый риск для worker и лишние этапы
Implement, Review и Verify по уже поставленному поведению.

Оставшиеся наблюдения не возвращают дубликат в разработку. Прежний `SA4000` в
`internal/worker/attempt_lifecycle_test.go:31` относится к отдельному
техническому долгу полного набора проверок. Устаревший статус CARD-0098
`awaiting Verify` — отдельный редакционный долг. Browser suite не доказывает
backend-поведение health-probe и не является барьером документального закрытия;
его инфраструктурная недоступность также должна учитываться отдельно.

## Технический подход и реальные файлы

Продуктовый подход уже реализован коммитом
`9af274d80462f6b10c4a95392a65e5022795a2e7` — поставкой PR #209, которая входит
в свежий `origin/main`:

- `internal/worker/health.go` направляет короткие command-probe через
  `runHealthCommand`; обёртка повторяет только `ErrCommandAlreadyRunning`, ждёт
  с context-aware timer и делит прежний timeout между ожиданием lock и запуском;
- `internal/worker/health_test.go` проверяет два совпадающих Claude probe,
  настоящую ошибку процесса и ограничение ожидания deadline;
- общий `runCommand` сохраняет неблокирующее поведение для остальных
  вызывающих сторон, что контролирует существующий тест в
  `internal/worker/command_test.go`.

Текущая поставка не меняет перечисленные исходники. Она добавляет только эту
спецификацию и отдельную карточку закрытия
`knowledge/cards/CARD-0156-concurrent-claude-health-probe-duplicate.md`.
Существующие CARD-0098 и её спецификация остаются историческим источником
поставленного решения и не редактируются.

## Последовательный план

1. Обновить `origin/main` и подтвердить, что implementation commit PR #209
   достижим из него и действительно содержит оба реальных файла реализации.
2. Выполнить четыре целевые worker-регрессии: конкурентный probe, настоящую
   ошибку, deadline ожидания и неизменный неблокирующий `runCommand`.
3. Зафиксировать решение владельца `CLOSE / DUPLICATE` в отдельной карточке
   текущей работы, не меняя CARD-0098 и продуктовый код.
4. Опубликовать только спецификацию и карточку закрытия. Не создавать следующие
   продуктовые стадии для этого дубликата.
5. Передать `SA4000`, устаревший статус CARD-0098 и инфраструктурную доступность
   browser suite отдельными находками, не смешивая их с исправлением health-probe.

## Критерии приёмки

1. CARD-0156 имеет статус `Closed — Duplicate` и прямо ссылается на CARD-0098,
   PR #209 и фактический полный implementation commit со словесной подписью.
2. Implementation commit является предком свежего `origin/main`; поставленные
   `internal/worker/health.go` и `internal/worker/health_test.go` присутствуют.
3. Четыре целевых теста завершаются с кодом 0 и подтверждают ожидание занятого
   probe без ослабления общего `runCommand`.
4. Diff текущей ветки относительно свежего `origin/main` содержит только эту
   спецификацию и CARD-0156; продуктовый код, UI и CARD-0098 не меняются.
5. Для текущего дубликата не планируются Implement, Review или Verify. `SA4000`,
   редакционное состояние CARD-0098 и browser-инфраструктура остаются отдельным
   техническим/редакционным долгом и не блокируют закрытие.

## Тест-план

Обязательная проверка:

`go test ./internal/worker -count=1 -run '^(TestConcurrentClaudeHealthChecksWaitForIdenticalProbe|TestClaudeHealthCheckPreservesCommandFailure|TestClaudeHealthCheckLockWaitHonorsTimeout|TestRunCommandSkipsConcurrentDuplicate)$'`

Она должна завершиться с кодом 0. Дополнительно выполнить read-only проверку
`git merge-base --is-ancestor 9af274d80462f6b10c4a95392a65e5022795a2e7 origin/main`
и `git diff --check`. Полный `just staticcheck` не является барьером этой
документальной поставки: известный `SA4000` расположен вне её diff. Browser
suite не запускается, поскольку работа не меняет наблюдаемое в браузере
поведение и web-зависимости в контейнере не установлены.

## Риски и решения

- Повторная реализация может разойтись с уже влитым решением. Поэтому исходники
  не меняются, а текущая работа закрывается как дубликат.
- Устаревший `awaiting Verify` в CARD-0098 может снова породить работу. Карточка
  не переписывается задним числом; редакционное исправление передаётся отдельно,
  а CARD-0156 однозначно запрещает продолжение текущего конвейера.
- Падение общего `staticcheck` может быть ошибочно приписано документационному
  diff. Область находки зафиксирована до изменений: это прежний тестовый файл,
  а сущность health-probe доказывается узкой командой с кодом 0.
- Browser suite может остаться недоступным из-за окружения. Он не покрывает
  backend-механику lock/retry; обязательный Go-тест непосредственно проверяет
  поставленное поведение.
- Параллельная работа может занять номер карточки. Перед финальным rebase и push
  номер и точный путь повторно проверяются по опубликованным веткам.
