# Серверный браузер для агентов и «Диалога»

## Решение

Factory использует установленный на сервере Chromium в headless-режиме. Один
runner обслуживает HTTP API «Диалога» и CLI `factory-worker browser`, доступную
агентам. Путь берётся из `FACTORY_BROWSER_EXECUTABLE`, системного `PATH` либо из
кэша Chromium, установленного Playwright; серверная установка описана скриптом
`ops/install-server-browser.sh`.

Chromium запускается от непривилегированного пользователя Factory со штатной
системной песочницей: отключающие sandbox флаги запрещены. Обязательный root-owned
launcher создаёт для каждого запуска отдельный network namespace и veth. Внутри
нет default route, а IPv4/IPv6 firewall разрешает единственное TCP-соединение с
allowlist-прокси. Если launcher не установлен, снимок не выполняется.
Go-runner посылает TERM только группе обёрток `sudo`/`fx`/launcher и ждёт
завершения cleanup. Chromium находится в отдельной сессии: только root-owned
launcher завершает его TERM/KILL и удаляет network namespace.

## Граница доступа

Разрешён только origin `https://staging-automation.tarser.net` и любые пути на
нём. Исходный URL проверяется до запуска Chromium. Весь трафик Chromium может
выйти из namespace только через локальный CONNECT-прокси, который допускает
этот host и порт 443; QUIC и любой прямой TCP, UDP или DNS egress отсекаются
firewall. Поэтому переход или HTTP-редирект на production, старые стенды,
внешний сайт, localhost или внутренний IP не получает соединение. Сам стенд
также резолвится один раз и соединение устанавливается только с публичным IP;
CGNAT, документационные и остальные специальные IPv4/IPv6-сети запрещены.

## Контракты

- CLI: `factory-worker browser -output <png> <url>`; таймаут по умолчанию 45 с,
  файл создаётся с правами 0600.
- API: `POST /api/v1/browser/capture`, JSON `{ "url": "..." }`; успешный ответ
  содержит канонический URL, `image/png` и base64-данные. Тело ограничено 4 KiB,
  PNG ограничен 4 МБ до кодирования, одновременно выполняется не более одного
  снимка, занятый слот возвращает 429.
- Окружение: перед первым выпуском владелец один раз устанавливает доверенные
  bootstrap и `fx`, затем `fx factory install-release-helper <commit>` принимает
  только точную вершину `origin/main` и транзакционно ставит root-owned helpers
  и browser-sandbox. Обычный выпуск никогда не исполняет `ops/*` из checkout от
  root; brain-installer получает закрытый root-owned снимок точного commit, а
  каждый устанавливаемый путь заранее проверяется через `lstat` с отказом на
  любом симлинке. После установки worker проверяет полную цепочку отмены, включая
  отказ прямых TCP, UDP и DNS по firewall counter.
- UI: на `/dialog` оператор вводит путь утверждённого стенда, получает снимок и
  отправляет его выбранной модели как обычное вложение.
- Ошибочный origin возвращает `browser_url_not_allowed`, отсутствие/сбой
  Chromium — `browser_unavailable` без раскрытия внутренней диагностики.

## Проверка

Unit-тесты покрывают точный allowlist, запрет CGNAT и специальных IPv4/IPv6,
обязательный sandbox-launcher, лимит PNG, ограничения размера и параллелизма API
до запуска runner, завершение упрямого потомка по таймауту и прикрепление
серверного снимка в «Диалоге». Root-интеграция `browser-sandbox check` поднимает
настоящий namespace/veth/firewall, читает счётчик отброшенных TCP, UDP и DNS и
через настоящий `factory-worker -> sudo/fx -> launcher` проверяет, что зависший
Chromium убит, а namespace удалён до возврата из отменённого Capture.
Production-сборка UI фиксируется в `web/dist`.

## Вне области

Production и прежние стенды, произвольный интернет, localhost, внутренние IP,
интерактивное управление вкладкой, хранение истории снимков и обход авторизации.
