# Закрыть повторное усиление Review как уже поставленное

## Цель и влияние на владельца

Закрыть текущую работу как `CLOSE / DUPLICATE`: защита Review от устаревшей
основной ветки уже находится в `main` в поставке «отдельной карточкой усилить
legacy fallback и fixture stale-cache» (PR #207). Владелец не оплачивает и не
принимает повторную реализацию, а состояние CARD-0111 перестаёт ошибочно
сообщать, что готовая поставка ещё ожидает слияния.

## Технический подход и реальные файлы

Продуктовый подход уже реализован коммитом
`e6c884a4387b92e3059d1385cc84a3bc22c95c3b`, который входит в историю
`origin/main`:

- `pilot/pilot.py` — `review_gate` использует результат свежего pinned snapshot,
  блокирует Review при ошибке инфраструктуры и не повышает legacy
  `branch_report` до authoritative fallback;
- `pilot/test_pilot.py` — `FreshDefaultBranchSnapshotTests` содержит fixture, где
  локальный cached main устарел, remote main продвинут, а scope вычисляется по
  свежим `base_sha...candidate_sha` без переключения observer branch.

Повторно эти файлы не изменять. Текущая отдельная поставка является только
документационной уборкой:

- `knowledge/cards/CARD-0111-legacy-fallback-stale-cache.md` — заменить
  предсливочный статус и неверную ссылку на фактический merged-коммит;
- `knowledge/specs/review-stale-base-duplicate-closeout.md` — зафиксировать
  решение владельца о закрытии дубликата, границы и проверяемые доказательства.

## Последовательный план

1. На свежем `origin/main` подтвердить, что фактический implementation commit
   входит в историю основной ветки и содержит изменения вне карточки.
2. Запустить целевой набор `FreshDefaultBranchSnapshotTests`, подтверждающий
   свежую pinned-основу, точный scope и fail-closed при сбое fetch/resolution.
3. Обновить CARD-0111: поставить завершённый статус, сослаться на фактическую
   поставку и явно удалить устаревшее действие «human merge».
4. Опубликовать только спецификацию и карточку. Не создавать Implement + Test,
   Review или Verify для повторного изменения продуктового кода.

## Критерии приёмки

- Работа классифицирована как `CLOSE / DUPLICATE`, повторная реализация не
  запланирована и продуктовые файлы не входят в документационный diff.
- CARD-0111 сообщает, что защита влита в `main` через PR #207, ссылается на
  фактический полный implementation SHA и не содержит действия «awaiting human
  merge».
- Указанный implementation commit достижим из свежего `origin/main` и содержит
  изменения `pilot/pilot.py` и `pilot/test_pilot.py`.
- `FreshDefaultBranchSnapshotTests` завершаются с кодом 0 и покрывают stale
  cached main, pinned SHA scope и инфраструктурную блокировку.
- Diff текущей работы относительно свежего `origin/main` содержит только эту
  спецификацию и CARD-0111.

## Тест-план

Обязательная проверка — запустить только целевой класс:
`python3 -m unittest -q pilot.test_pilot.FreshDefaultBranchSnapshotTests`.
Он должен завершиться с кодом 0. Отдельно read-only проверкой
`git merge-base --is-ancestor e6c884a4387b92e3059d1385cc84a3bc22c95c3b origin/main`
подтвердить, что закрываемая поставка действительно в основной ветке. Полный
набор не нужен: продуктовый код в этой работе не меняется.

## Риски и решения

- **Повторная поставка расходится с уже влитой защитой.** Решение: закрыть
  дубликат и не запускать следующие продуктовые стадии.
- **Карточка снова выглядит незавершённой из-за SHA документационного HEAD.**
  Решение: хранить именно `Implementation commit` с подписью результата, не
  подменять его текущим HEAD карточки.
- **Документационная уборка смешивается с кодовым исправлением.** Решение: diff
  ограничен спецификацией и CARD-0111; реальные продуктовые файлы перечислены
  только как уже поставленные.
- **Локальный `origin/main` устарел.** Решение: перед проверкой и сдачей fetch
  `origin main`, а принадлежность implementation commit проверять по свежему
  remote-tracking ref.

## Карточка работы

`knowledge/cards/CARD-0111-legacy-fallback-stale-cache.md` — карточка фактически
влитой защиты. В текущей работе она переносится из ошибочного состояния
«ожидает слияния» в `Done` и связывается с поставкой PR #207; новая карточка для
повторной кодовой работы не создаётся.
