# Документные изменения проходят лёгкие ворота выпуска

## Цель и влияние на владельца

Изменение только Markdown-документов не должно ждать полного набора UI- и
Go-тестов, который проверяет неизменившийся продуктовый код. Владелец быстрее
получает опубликованные спецификации, карточки и руководства, при этом любое
изменение исполняемого содержимого по-прежнему проходит полный Gate.

Оптимизация относится только к выбору проверок. Криптографическая фиксация
Git-кандидата, сборка артефактов, снимок базы, rollback, переключение поколения
и проверка живых сервисов остаются обязательными и не меняются.

## Технический подход и реальные файлы

В `ops/fx-factory-release` после root-owned clone, checkout и получения `$sha`,
но до `npm ci`, определить первый родитель кандидата через `/usr/bin/git`.
Лёгкий путь разрешать только когда одновременно выполнены условия:

- у кандидата ровно один родитель;
- diff родитель → кандидат непустой;
- каждая запись diff имеет обычный файловый mode с обеих существующих сторон,
  не меняет mode и имеет путь с окончанием `.md`;
- нет rename/copy, submodule, symlink, неизвестного статуса или ошибки Git.

Удаление или добавление обычного `.md` допустимо, если существующая сторона
имеет mode `100644`. Любая неоднозначность должна fail closed выбирать текущий
полный Gate. Список получать из NUL-delimited raw diff, не разбирать пробелы и
переводы строк в именах shell-циклом.

Для docs-only кандидата пропустить `npm ci` и `run_parallel_test_gates`, вместо
них выполнить лёгкую обязательную проверку
`git diff --check <parent> <candidate>` доверенным Git и явно написать в выводе,
почему выбран лёгкий Gate. После неё продолжить существующую сборку и выпуск без
изменений. Для остальных кандидатов сохранить нынешние `npm ci`, TypeScript,
UI, `go test ./...` и интеграционный release-сценарий.

В `ops/test-fx-factory-release.sh` расширить hermetic fixture отдельными
сценариями docs-only и ложных совпадений. Тест должен наблюдать журнал команд,
а не полагаться только на текст сообщения.

## Последовательный план

1. Добавить в `ops/fx-factory-release` fail-closed классификатор raw Git diff с
   явным результатом `docs_only=1` только для обычных `.md`.
2. Развести участок установки зависимостей и тестовых ворот: docs-only запускает
   `git diff --check`, любой другой результат — неизменённый полный Gate.
3. Сохранить общую нижнюю часть выпуска: сборки, snapshot, generation manifest,
   остановку/запуск сервисов, health-check и rollback.
4. Дополнить `ops/test-fx-factory-release.sh` положительным docs-only сценарием
   и таблицей отрицательных сценариев с доказательством выбора полного Gate.

## Критерии приёмки

- Одиночный commit, меняющий только обычные `.md`, проходит `git diff --check`,
  не запускает `npm ci`, UI/Go тесты и интеграционный Gate, затем доходит до
  существующей сборки и успешной поставки.
- Изменение `.go`, `.ts`, `.sh`, конфигурации, mode, symlink или submodule, а
  также смешанный diff запускает полный набор ворот.
- Merge commit, commit без родителя, пустой diff, rename/copy и ошибка чтения
  Git не получают лёгкий путь.
- Пути с пробелами обрабатываются без разбиения; необычные имена не позволяют
  скрыть недокументный файл.
- Ошибка `git diff --check` останавливает выпуск до сборки и мутаций.
- Trusted Git/blob проверки, build, snapshot, rollback, manifest и живые
  проверки не ослаблены; формат успешного результата брокера не меняется.

## Тест-план

- Целевой shell-suite создаёт реальный Git commit только с `knowledge/*.md` и
  подтверждает лёгкую проверку, отсутствие четырёх тяжёлых команд и успешную
  поставку.
- Табличные fixtures проверяют `.go`, смешанный diff, executable-bit у `.md`,
  symlink с именем `.md`, rename, merge commit и ошибку определения родителя;
  каждый обязан зафиксировать полный Gate.
- Отдельный docs-only fixture с trailing whitespace подтверждает ненулевой код
  `git diff --check` и отсутствие сборки/остановки сервисов.
- Выполнить `bash -n ops/fx-factory-release ops/test-fx-factory-release.sh` и
  целевой `bash ops/test-fx-factory-release.sh`.

## Риски и решения

- **Обход классификатора именем файла.** Использовать raw NUL-delimited diff и
  проверять status, mode и оба пути, а не только суффикс строки.
- **Документ с исполняемым смыслом.** Лёгкий список ограничен `.md`; workflow,
  SQL, JSON/YAML, HTML и shell всегда идут полным путём.
- **Непроверенная история merge.** Merge commit не оптимизировать: полный Gate
  дешевле ошибочного доверия к неверной базе сравнения.
- **Ослабление защищённого выпуска.** Не переносить классификацию перед
  root-owned checkout/проверку SHA и не менять общую цепочку после ворот.
- **Хрупкие тесты времени.** Проверять фактически вызванные команды и порядок,
  а не длительность выполнения.
