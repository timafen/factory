# Доверенный release-gate берёт Git-дерево кандидата

## Цель и влияние на владельца

Полный полигон выпуска должен одинаково работать при прямом запуске из checkout
и при штатном запуске извлечённой, закрытой от подмены копии gate. Во втором
случае рядом с `test-fx-factory-release.sh` находится только минимальный набор
доверенных зависимостей, а не Git-репозиторий. Полигон должен брать исходное
дерево из уже выбранного clone кандидата и не требовать ещё одной полной копии
репозитория в доверенный каталог.

Для владельца это означает, что глубокая проверка выпуска не падает только
из-за безопасного расположения gate и проверяет именно выбранную ревизию до
установки. Защита самого gate от подмены и состав проверочных сцен не меняются.

## Технический подход и реальные файлы

Реализация ограничена `ops/test-fx-factory-release.sh`:

- после вычисления `SCRIPT_DIR` определить `FIXTURE_TREE` как родительский
  каталог скрипта;
- проверить его как Git checkout командой с абсолютным `/usr/bin/git`; если
  рядом с gate репозитория нет, выбрать текущий рабочий каталог (`PWD`);
- в `make_fixture` строить исходную копию сцены через
  `git -C "$FIXTURE_TREE" archive HEAD`, а не всегда через `SCRIPT_DIR/..`.

При обычном запуске `SCRIPT_DIR/..` остаётся корнем репозитория, поэтому источник
не меняется. При глубокой проверке `ops/fx-factory-release` сначала делает
`cd "$work/src"`, а затем запускает извлечённый доверенный gate; следовательно,
его `PWD` — clone выбранного кандидата. После распаковки архива fixture, как и
раньше, поверх дерева получает криптографически проверенные копии
`ops/fx-factory-release` и `ops/test-fx-factory-release.sh` из доверенного
каталога. `ops/fx-factory-release` — реальный вызывающий контекст, но менять его
для этой работы не требуется.

Публичные API, UI, схема данных, режимы release-gate и права доверенного каталога
не меняются.

## Последовательный план

1. В начале `ops/test-fx-factory-release.sh` ввести единый источник
   `FIXTURE_TREE`, предпочитающий Git-дерево рядом со скриптом и использующий
   `PWD` только для извлечённой доверенной копии.
2. Перевести единственный `git archive HEAD` в `make_fixture` на этот источник,
   не добавляя копирование всего дерева в доверенный каталог.
3. Сохранить без изменений извлечение и проверку blob-объектов gate в
   `ops/fx-factory-release`, сценарий `trusted-gate-real-race`, handshake и
   конкурентную попытку подмены.
4. Выполнить синтаксическую проверку и целевой shell-полигон из корня Git
   checkout; убедиться, что успешен как обычный набор сцен, так и запуск
   настоящего извлечённого gate.

## Критерии приёмки

- Прямой запуск `ops/test-fx-factory-release.sh` архивирует `HEAD` репозитория,
  содержащего сам скрипт.
- Извлечённая доверенная копия, рядом с которой нет `.git`, архивирует `HEAD`
  clone кандидата из `PWD`, переданного контрактом release-driver.
- Fixture содержит полное дерево выбранного кандидата, после чего проверенные
  trusted-копии release helper и gate по-прежнему накладываются поверх него.
- Для выбора источника используется `/usr/bin/git`; подмена `git` через `PATH`
  не влияет на решение.
- Если ни каталог скрипта, ни `PWD` не позволяют выполнить `git archive HEAD`,
  проверка завершается ненулевым кодом, а не строит неполную сцену.
- `trusted-gate-real-race` подтверждает настоящий gate после handshake и не
  допускает успешной подмены каталога; существующие проверки не ослаблены.
- Изменение не требует второй полной копии Git-дерева в root-owned каталог.

## Тест-план

- `bash -n ops/test-fx-factory-release.sh` — проверить shell-синтаксис.
- `bash ops/test-fx-factory-release.sh` — обязательный целевой полигон. Он
  должен завершиться кодом 0 и пройти `trusted-gate-real-race`, где настоящий
  gate запускается из отдельной доверенной копии при `PWD`, равном clone
  кандидата.
- Просмотреть журнал сцены и убедиться в событии
  `real-extracted-gate-after-handshake`, отсутствии оставшегося
  `trusted-gate-*` в доступном для рабочего пользователя каталоге и отсутствии
  утёкших процессов fixture.
- Отдельно проверить fail-closed поведение запуском копии скрипта вне Git
  checkout с рабочим каталогом вне Git: команда обязана завершиться ненулевым
  кодом на попытке `git archive HEAD`.

## Риски и решения

- Риск: `PWD` станет неявным и хрупким источником. Решение: считать его частью
  уже существующего контракта `run_parallel_test_gates`, который явно делает
  `cd "$work/src"` непосредственно перед вызовом trusted gate, и закрепить это
  сценарием `trusted-gate-real-race`.
- Риск: запуск из произвольного Git-репозитория проверит не то дерево. Решение:
  fallback разрешён только когда каталог рядом со скриптом не является Git
  checkout; штатный release-driver задаёт `PWD` clone кандидата.
- Риск: поиск Git через пользовательский `PATH` позволит подменить определение
  источника. Решение: использовать абсолютный `/usr/bin/git` и для проверки, и
  для архивации.
- Риск: fallback скроет отсутствие обоих репозиториев. Решение: не подавлять
  ошибку `git archive`; `set -euo pipefail` останавливает полигон до неполной
  fixture.
- Решение по области: не менять механизм извлечения trusted blob-объектов,
  права каталогов, release-driver, UI или продуктовые исходники.
