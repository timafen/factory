# История работы простыми словами вместо простыни вывода

## 1. Цель и влияние на пользователя

На странице задачи история работы должна отвечать на вопрос «что сейчас сделал исполнитель», а не заставлять владельца разбирать протокол Codex/Claude Code, команды и длинный stdout. Пользователь увидит короткие русские записи о сообщениях исполнителя, запуске и результате проверок, изменении файлов и ошибках; служебные события и содержимое вывода инструментов останутся скрыты.

Изменение касается только представления уже полученных событий. Хранение событий, API и поведение исполнителей не меняются.

## 2. Технический подход

Текущий экран `web/src/TaskDetail.tsx` получает события `/api/v1/attempts/{id}/events`, пропускает каждое через `eventSummary()` из `web/src/format.ts` и показывает ненулевые результаты в `event-list`. Форматтер уже распознаёт конверты Codex и Claude Code, однако возвращает технические английские подписи (`Command`, `Tool`, `Runtime`) и для потоковых событий может показать до 500 символов сырого вывода.

Минимальное изменение:

- в `web/src/format.ts` сохранить существующий разбор обоих runtime, но заменить пользовательские подписи и статусы на короткие русские формулировки;
- команды описывать как действие и результат без `aggregated_output`; результаты tool-вызовов и изменений файлов — без payload;
- события `stdout`/`stderr` не показывать как обычный ход работы; ошибку показывать только когда протокол даёт отдельное структурированное сообщение об ошибке;
- неизвестные объектные и lifecycle/telemetry-события скрывать, а не превращать в бессодержательное «Runtime update»;
- сообщения ассистента и явные продуктовые `message`/строковые progress-события сохранить: это полезный человеческий контекст;
- в `web/src/format.test.ts` закрепить одинаковые правила для Codex, Claude Code, команд, инструментов, файлов, ошибок, сырых потоков и неизвестных событий.

`web/src/TaskDetail.tsx`, стили, серверный API и тип `AttemptEvent` менять не требуется: контракт `EventSummary | null` уже позволяет отфильтровать шум до отрисовки.

### Данные и API

Изменений схемы, миграций и HTTP API нет. Меняется только клиентское отображение существующего payload.

## 3. План

1. Дополнить табличные тесты `eventSummary()` ожидаемыми русскими записями и отсутствием сырого stdout/stderr, служебных идентификаторов и неизвестных payload.
2. Обновить ветви форматирования Codex и Claude Code в `web/src/format.ts`, сохранив сообщения исполнителя и структурированные ошибки.
3. Удалить пользовательский fallback для неизвестных объектных событий и вернуть `null` для шума.
4. Запустить целевой тест форматтера; затем typecheck и lint веб-клиента.

## 4. Критерии приёмки

1. Успешная и неуспешная команда отображаются короткой русской фразой с самой командой и кодом ошибки при его наличии; захваченный вывод не отображается.
2. Вызов инструмента и изменение файлов отображаются как понятное действие/результат без внутренних payload, session ID и содержимого tool result.
3. Текстовое сообщение исполнителя и отдельная структурированная ошибка остаются видимыми без JSON-конверта runtime.
4. Lifecycle, telemetry, reasoning, неизвестные объектные события и stdout/stderr не добавляют строк в историю.
5. Правила одинаково работают для событий Codex и Claude Code; порядок оставшихся событий не меняется.
6. API, сервер, хранение событий и остальные экраны не изменены.

## 5. План тестирования

- Обновить `web/src/format.test.ts`: проверки русских формулировок для успешной/неуспешной команды, tool call, file change, сообщений и ошибок обоих runtime.
- Добавить отрицательные проверки: в summary нет `aggregated_output`, tool result, служебного ID; stdout/stderr и неизвестный объект дают `null`.
- Обязательная целевая команда из корня репозитория: `cd web && npm test -- --run src/format.test.ts`.
- Перед передачей Verify дополнительно выполнить `cd web && npm run typecheck` и `cd web && npm run lint`.

## 6. Риски и решения

- Скрытие stdout может убрать полезную диагностику. Решение: история предназначена владельцу; структурированные ошибки и сообщения исполнителя остаются. Отдельный режим технического журнала не входит в эту работу.
- Свободный текст команды может содержать секрет. Эта спецификация сохраняет текущий показ самой команды, но запрещает показывать её вывод. Маскирование аргументов команд требует отдельной модели редактирования и является расширением области.
- Локализация всей страницы задачи не входит в задачу: меняются только записи истории. Переименование `Progress`, `Attempts` и других элементов следует делать отдельной согласованной работой.
- Нужное решение человека до реализации отсутствует; предложенная область не меняет данные и обратима на уровне UI.
