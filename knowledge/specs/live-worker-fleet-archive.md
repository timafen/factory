# Экран исполнителей показывает живой парк и архив регистраций

## Цель и влияние на владельца

Экран «Исполнители» должен отделять актуальный парк от регистраций машин,
которые давно перестали подавать сигнал. В основном списке остаются все
исполнители с `last_heartbeat` моложе 7 суток: первые 30 секунд они имеют
прежний статус `Online`, затем до истечения 7 суток — `Offline`. При возрасте
последнего heartbeat 7 суток и более регистрация показывается в архиве.

Владелец видит ёмкость именно текущего парка, не теряя историю старых машин.
Архивирование является только представлением: запись не удаляется и не
изменяется на сервере, а новый heartbeat возвращает исполнителя в основной
список при следующем штатном обновлении экрана.

## Технический подход и реальные файлы

`internal/protocol/types.go` уже задаёт `WorkerOnlineWindow = 30 * time.Second`.
`internal/controlplane/store.go` в `Workers` возвращает все регистрации без
фильтра и в `scanWorker` вычисляет `online` по этому окну. Маршрут
`GET /api/v1/workers` в `internal/controlplane/http.go` отдаёт массив целиком.
`web/src/App.tsx` обновляет запрос исполнителей каждые 10 секунд, а
`web/src/Workers.tsx` сейчас показывает весь массив одной таблицей и включает
его целиком в `Registered`.

Изменение выполняется только в web-представлении:

- в `web/src/Workers.tsx` ввести константу окна архива 7 суток и на каждом
  render разделять полученные регистрации по `last_heartbeat`;
- возраст `>= 7 * 24 * 60 * 60 * 1000` считать архивным, возраст меньше порога
  — текущим; вплоть до последней миллисекунды перед порогом исполнитель
  остаётся в основном списке;
- не пересчитывать `online` на клиенте и не менять 30-секундный контракт:
  статус строки берётся из серверного `worker.online`;
- сводку строить по текущему парку: `Current` — число регистраций моложе 7
  суток, `Online` — текущие с `online=true`, `Available slots` — свободные
  слоты только текущих online/healthy исполнителей; отдельный `Archived`
  показывает число старых регистраций;
- основной список оставить раскрытым. Непустой архив разместить ниже в
  сворачиваемом блоке `Archive (N)`, закрытом по умолчанию; архивные строки
  сохраняют имя, runtime, последний heartbeat и переход в существующую
  карточку исполнителя;
- если регистраций нет вообще, сохранить `No workers registered`. Если все
  регистрации архивные, вместо таблицы текущего парка показать `No current
  workers`, но оставить сводку и доступ к архиву;
- не фильтровать общий query cache и не менять массив, который `App.tsx`
  передаёт в окно назначения: архив относится только к экрану списка;
- в `web/src/styles.css` оформить заголовок/состояние архива и четыре показателя
  сводки без горизонтального переполнения на ширине 390 px;
- в новом `web/src/Workers.test.tsx` зафиксировать обе временные границы и
  автоматический возврат после нового heartbeat;
- в `web/e2e/control-plane.spec.ts` расширить проверку `/workers`: недавно
  отключённая машина видна в основном парке, старая скрыта в закрытом архиве,
  после раскрытия доступна и открывает прежнюю detail-страницу; мобильный экран
  не получает горизонтальный скролл.

Схема SQLite, Store, HTTP-контракт, `Worker` type и 10-секундный polling не
меняются. Порядок строк внутри обеих групп сохраняет порядок ответа API.
Невалидный или будущий `last_heartbeat` не должен молча скрывать регистрацию:
такую запись консервативно оставить в основном списке.

## Последовательный план

1. Вынести в `Workers.tsx` чистую проверку возраста регистрации и разделить
   входной массив на текущий парк и архив с точной границей 7 суток.
2. Перевести сводку и основной список на текущий парк, добавить отдельный
   закрытый архив и различить состояния «нет регистраций»/«все в архиве».
3. Добавить стили четырёх показателей, заголовка архива и адаптивного блока,
   переиспользуя существующую разметку строки исполнителя.
4. Добавить компонентный тест для 30 секунд, 7 суток, невалидной даты и
   перемещения той же регистрации обратно после нового heartbeat.
5. Расширить Playwright-сценарий списка и мобильной ширины, затем выполнить
   целевой Vitest, typecheck и целевой browser test.

## Критерии приёмки

- Исполнитель с heartbeat не старше 30 секунд находится в основном списке и
  имеет прежний серверный статус `Online`.
- Исполнитель старше 30 секунд, но моложе 7 суток, остаётся в основном списке
  со статусом `Offline`.
- При возрасте heartbeat ровно 7 суток и старше исполнитель отсутствует в
  раскрытом основном списке и доступен в закрытом по умолчанию `Archive (N)`.
- `Current`, `Online` и `Available slots` не учитывают архивные регистрации;
  `Archived` равен размеру архива.
- Новый heartbeat той же регистрации переносит её из архива в основной список
  не позднее следующего 10-секундного refetch, без перезагрузки страницы,
  удаления или повторной регистрации в БД.
- Из архивной строки можно открыть неизменённую detail-страницу исполнителя;
  API и другие потребители полного списка не меняют поведение.
- Пустой ответ показывает прежнее глобальное empty state, а полностью архивный
  парк — отдельное состояние текущего списка и доступный архив.
- На ширине 390 px сводка, основной список и раскрытый архив не создают
  горизонтальный скролл.

## Тест-план

- `web/src/Workers.test.tsx`: зафиксировать время, передать online, недавно
  offline, heartbeat на миллисекунду до порога, heartbeat ровно на пороге,
  старую и невалидную регистрации; проверить группы и четыре счётчика.
- В том же тесте через `rerender` заменить старый `last_heartbeat` актуальным и
  проверить исчезновение из архива и появление в основном списке как `Online`.
- Проверить два empty state отдельно: пустой массив и массив только из архива.
- `web/e2e/control-plane.spec.ts`: проверить закрытый архив, раскрытие, переход
  в detail и отсутствие переполнения на 390×844.
- Целевые команды реализации: `cd web && npm test -- Workers.test.tsx`,
  `cd web && npm run typecheck`, затем соответствующий Playwright test.

## Риски и решения

- **Расхождение часов браузера и сервера.** Граница представления использует
  клиентское время, но сервер остаётся источником heartbeat и `online`. При
  невалидном/будущем времени запись остаётся видимой; отдельный server clock в
  API ради семидневной группировки не вводится.
- **Пограничное мерцание.** Сравнение задано явно: до 7 суток основной парк,
  начиная с 7 суток архив. Перегруппировка происходит на render/refetch; новый
  таймер не добавляется, поскольку существующий polling обновляет экран каждые
  10 секунд.
- **Случайное изменение маршрутизации.** Разделение выполняется внутри
  `WorkersView`, а исходный query cache остаётся полным для Delegate modal,
  detail и прочих потребителей.
- **Архив ошибочно воспринимается как удаление.** В UI нет destructive action;
  архивная строка остаётся открываемой, а Store/БД/HTTP не изменяются.
- **Старая регистрация искажает ёмкость.** Все операционные показатели, кроме
  явного `Archived`, рассчитываются только по текущему парку.
