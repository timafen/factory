# CARD-0083: закрыть повторную разработку Gate как дубликат

## Цель и влияние на владельца

Не запускать четвёртую попытку изменения launcher-файлов для ошибки Gate, которую
уже исправил и доставил в `main` PR #197 «Перенести безопасный Gate поверх свежей
основной ветки». Владелец получает однозначное решение `CLOSE / DUPLICATE` без
нового конфликта с `main`, повторного цикла разработки и риска изменить уже
проверенное release-поведение.

Оставшийся дефект относится только к учёту: карточка Gate всё ещё сообщает
`awaiting human merge`, а номер `CARD-0083` одновременно занят карточкой Settings.
Этот долг вынесен в отдельную `CARD-0106`; он не возвращает Gate в разработку.

## Технический подход и реальные файлы

Продуктовых изменений для этой работы нет. Свежий `main` уже содержит коммит
`76d16c5191dcc8c44a001ffb71dbbaebf183f573` — результат PR #197. В нём изменены
реальные файлы launcher и его регрессии:

- `ops/fx-factory-release` принимает результат настоящей Gate-цепочки и не
  доверяет раннему успеху форкающего launcher;
- `ops/test-fx-factory-release.sh` проверяет fork/failure, trusted launcher,
  readiness, cleanup, rollback и отсутствие установки после ошибки Gate.

Повторно менять эти файлы, cherry-pick-ить прежнюю ветку либо разрешать их
конфликты запрещено: кандидат и `main` уже совпадают по доставленному решению.
Устаревший статус `knowledge/cards/CARD-0083-real-session-before-gate.md` и
дублирующий номер у
`knowledge/cards/CARD-0083-settings-save-without-first-verify.md` описаны в
отдельной учётной карточке, а не исправляются этой поставкой.

## Последовательный план

1. Зафиксировать решение владельца `CLOSE / DUPLICATE` и ссылку на доставивший
   исправление PR #197.
2. Подтвердить, что implementation commit PR #197 присутствует в свежем `main`
   и действительно меняет оба launcher-файла.
3. Выполнить синтаксическую проверку launcher и тестового shell-сценария; код 0
   является обязательным барьером закрытия.
4. Не создавать стадию Implement + Test и не переносить изменения из прежних
   веток CARD-0083.
5. Передать исправление карточных метаданных отдельной `CARD-0106` без связи с
   продуктовой разработкой Gate.

## Критерии приёмки

- Работа закрыта как уже выполненный дубликат, а не возвращена в разработку.
- PR #197 и его implementation commit являются предками свежего `main`.
- `ops/fx-factory-release` и `ops/test-fx-factory-release.sh` не меняются в
  ветке этой Specification.
- Обязательная shell syntax-проверка обоих доставленных файлов завершается с
  кодом 0.
- Устаревший статус и повтор номера CARD-0083 имеют отдельную учётную карточку;
  эта находка не считается продуктовым дефектом Gate.
- Diff этапа содержит только эту спецификацию и карточку текущей учётной работы.

## Тест-план

На этапе Specification выполнить быстрый обязательный барьер:
`bash -n ops/fx-factory-release ops/test-fx-factory-release.sh`.

Повторный полный `bash ops/test-fx-factory-release.sh` не требуется: он уже прошёл
при проверке PR #197, а эта работа не меняет исполняемые файлы. Если последующая
проверка обнаружит отличие launcher-файлов от `main`, закрытие надо остановить как
ошибку базовой ветки, а не начинать разрешение конфликтов в этом документальном
этапе.

## Риски и решения

- Риск: оркестратор увидит старое `awaiting human merge` и снова создаст Implement.
  Решение: настоящее решение владельца и эта спецификация имеют приоритет;
  метаданные исправляются только отдельной CARD-0106.
- Риск: механическое переименование одной из двух CARD-0083 сломает ссылки из
  истории. Решение: CARD-0106 требует сначала найти ссылки и выбрать каноническую
  карточку; эта работа ничего не переименовывает.
- Риск: повторный rebase старой ветки снова конфликтует в двух launcher-файлах.
  Решение: старая ветка не является кандидатом, потому что её результат уже в
  `main` через PR #197.
- Решение: полный release-suite не перезапускается без изменения кода; достаточно
  синтаксического барьера и доказательства предка, уже подтверждённых контекстом
  Triage.
