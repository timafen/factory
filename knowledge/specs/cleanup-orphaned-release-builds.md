# Безопасная очистка осиротевших папок сборки Factory

## Цель и влияние на владельца

Прерванный выпуск может оставить в каталоге релизов крупную папку `build-*`.
Следующий штатный выпуск должен освобождать это место сам, прежде чем создавать
новую сборку. Владелец получает предсказуемое восстановление только артефактов
выпуска: поколения, указатели текущего/предыдущего выпуска и данные иных
автоматизаций не меняются. Ручная очистка production и политика для любых иных
папок не входят в эту работу.

## Технический подход и реальные файлы

В `ops/fx-factory-release` release lock уже успешно захватывается строками
286–288, а `$REL` и `$GENERATIONS` подготавливаются непосредственно после него.
Перед `as_user mktemp -d "$REL/build-XXXXXX"` (сейчас строка 369) добавить
локальную cleanup-функцию и вызвать её после подготовки `$REL`, но до создания
новой рабочей папки и любых build/gate действий.

Функция перечисляет только непосредственных детей физического `$REL` с именем
`build-*`. Для каждого кандидата она подтверждает, что это каталог, не symlink,
а его канонический путь остаётся непосредственным ребёнком канонического `$REL`.
Только такой кандидат удаляется через уже доверенный `$TRUSTED_RM -rf --`.
Несоответствие проверки не обходится рекурсивно и не удаляется; скрипт выводит
понятное предупреждение и продолжает с безопасными объектами. Маска не
применяется к `generations`, не является рекурсивным поиском и не касается
`current`, `previous`, `transaction`, lock либо других имён.

В `ops/test-fx-factory-release.sh` дополнить fixture-сценарий: до `run_release`
создать устаревший реальный `$REL/build-orphaned` с marker-файлом, обычную
нерелизную папку и symlink `build-*` на объект вне `$REL`. После успешного
выпуска проверить удаление только реальной осиротевшей папки, сохранность
нерелизной папки и внешнего target/symlink. Существующие аварийные сценарии
остаётся запускать без изменения их rollback/cleanup ожиданий.

## Последовательный план

1. После release lock подготовить и канонизировать `$REL`; реализовать узкую
   проверку непосредственного ребёнка `build-*` без follow symlink.
2. Удалять только прошедшие проверку реальные каталоги доверенным `rm` до
   нового `mktemp`; логировать удаление и безопасный пропуск.
3. Добавить в shell fixture сценарий осиротевшей сборки с marker, чужой папкой
   и symlink за пределы `$REL`.
4. Прогнать целевой release fixture и проверку синтаксиса; убедиться, что
   успешный выпуск и ранее существующие rollback сценарии сохраняются.

## Критерии приёмки

1. После захвата release lock и до нового build-каталога следующий выпуск
   удаляет устаревший реальный верхнеуровневый `$REL/build-*`.
2. `generations`, `current`, `previous`, `transaction`, lock и все объекты с
   именем вне `build-*` остаются нетронутыми.
3. Symlink `build-*`, а также кандидат, канонический путь которого выходит из
   `$REL`, не передаётся рекурсивному удалению; внешний объект сохраняется.
4. Успешный выпуск по-прежнему публикует поколение, а ошибка/сигнал сохраняют
   нынешние гарантии trap-cleanup и rollback.
5. Новый fixture доказывает orphaned-build сценарий в изолированном каталоге.

## Тест-план

- `bash -n ops/fx-factory-release ops/test-fx-factory-release.sh` проверяет
  shell-синтаксис.
- `bash ops/test-fx-factory-release.sh` запускает новый orphaned-build сценарий
  вместе с уже существующими успешными, ошибочными и crash-cleanup сценариями.
- В новом сценарии явно проверить marker удалённого реального каталога,
  сохранность чужой папки и доступность target, на который указывает symlink.

## Риски и решения

- Широкий glob может затронуть чужую автоматизацию: искать только первый
  уровень `$REL` и принимать исключительно `build-*`.
- `rm -rf` опасен на symlink/path traversal: перед ним обязательны type,
  no-symlink и canonical-parent проверки; при сомнении объект пропускается.
- Очистка до lock создаст гонку двух выпусков: вызывать её только после
  успешного `flock`.
- Очистка может ошибочно изменить retention: не читать и не менять
  `$REL/generations`; существующий post-commit retention остаётся отдельно.
