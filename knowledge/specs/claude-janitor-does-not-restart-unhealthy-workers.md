# Спецификация: санитар не перезапускает Claude из-за одного unhealthy

## Цель и влияние на владельца

Сейчас `ops/factory-janitor.sh` считает достаточным условием для stop/start
online-воркера отсутствие активных попыток и статус `health != healthy`.
Для Claude Code это создаёт цикл: проверка здоровья снова публикует unhealthy,
санитар без изменения причины повторно останавливает и запускает службу, а
владелец получает простои и шум в журнале без освобождения retained-результата.
После изменения санитар будет освобождать только offline-воркеры с retained
worktrees; online/unhealthy останется наблюдаемым в control plane и будет
восстанавливаться собственной периодической health-проверкой воркера.

## Технический подход и реальные файлы

Изменить только `ops/factory-janitor.sh` и его целевой сценарий
`ops/test-factory-janitor.sh`.

В выборке работников убрать `online_and_unhealthy` из условия освобождения.
Оставить точное условие `!online && retained_worktrees && active_count == 0`.
При необходимости добавить диагностическую строку для online/unhealthy без
stop/start, чтобы оператор видел причину пропуска; такая строка не должна
резервировать попытку в `FACTORY_JANITOR_STATE`. Existing retained cleanup,
карантин, `git worktree prune` и точечный POST очистки не меняются.

Тестовая фикстура должна сохранить offline Claude с retained worktree и
добавить online unhealthy Claude без retained worktree. Проверить, что первый
освобождается, а второй не получает `systemctl stop/start`, не появляется в
журнале как освобождённый и не расходует лимит повторных попыток. Online
healthy с retained также должен остаться нетронутым. Сценарии ошибки POST и
сохранности карантина остаются регрессиями.

## Последовательный план

1. Зафиксировать в shell-выборке единственный кандидат: offline, idle,
   retained.
2. Удалить ветку действия для online/unhealthy и, при необходимости,
   журналировать пропуск без изменения state-файла.
3. Расширить `ops/test-factory-janitor.sh` проверками отсутствия stop/start и
   отсутствия резервирования для online/unhealthy.
4. Запустить целевой сценарий и проверить diff только документов этой работы.

## Критерии приёмки

1. Online/unhealthy Claude не останавливается и не запускается санитаром.
2. Повторные циклы санитаря не увеличивают счётчик попыток для online/unhealthy.
3. Offline idle Claude с retained по-прежнему переносится в карантин и
   подтверждается через существующий API только после успешного локального
   удаления/переноса.
4. Online healthy и активные воркеры не затрагиваются.
5. Ошибка API не удаляет карантин и фиксируется в журнале.

## Тест-план

Основная проверка — `bash ops/test-factory-janitor.sh`: mock `systemctl` пишет
вызовы stop/start, после запуска сценарий требует ноль вызовов для online
unhealthy и наличие вызовов только для offline retained. Дополнительно
проверяются payload retained, карантин, повторный запуск с ошибкой curl,
`bash -n ops/factory-janitor.sh` и `git diff --check`.

## Риски и решения

- Риск: online/unhealthy дольше остаётся недоступным для задач. Решение:
  worker продолжает собственные health/registration-тиκеры, а санитар не
  маскирует неисправность разрушительным рестартом; оператор видит статус.
- Риск: retained offline останется без очистки при активной попытке. Решение:
  сохранить текущий guard `active_count == 0`.
- Риск: изменение затронет действующее восстановление retained. Решение:
  не менять карантин, prune, API и лимит для offline-кандидатов.
