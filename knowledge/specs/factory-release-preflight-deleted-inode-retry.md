# Повторная предполётная проверка выпуска при deleted-inode

## Цель

Повторный запуск после обрыва supervisor должен иметь отдельный, однозначный
результат. Если активный process использует удалённый inode, выпуск обязан
остановиться до создания generation и любой мутации, сохранив unit и полный
вывод. Старую попытку нельзя считать успешной, а проверку `/proc/<pid>/exe`
нельзя ослаблять.

## Технический подход

- `ops/fx-factory-release` уже проверяет `MainPID` каждого активного unit через
  `/proc/<pid>/exe` и завершает gate с сообщением `процесс <unit> использует
  deleted-inode` и кодом 4.
- `ops/test-factory-release-systemd.sh` проверяет реальный systemd fixture и
  показывает deleted inode после замены executable.
- `ops/test-fx-factory-release.sh` должен изолированно доказать отказ до
  mutation, точное имя unit и отсутствие journal/current generation.
- После отказа в эксплуатации перезапускается только названный unit, затем
  preflight повторяется один раз; новый обрыв supervisor остаётся
  неопределённым и сопровождается полным voyage-log.

## Критерии приёмки

1. Повторный запуск имеет отдельный результат и не наследует статус обрыва.
2. При deleted inode release прекращается до публикации generation, замены
   бинарей, миграции или перезапуска сервисов.
3. Диагностика содержит unit, последний именованный шаг, полный вывод и код
   завершения; потеря supervisor output не маскирует результат.
4. После штатного restart конкретного unit следующий preflight либо проходит,
   либо снова выдаёт точную fail-closed причину.
5. Проверка `/proc/<pid>/exe` не ослабляется, и заменённый путь не считается
   доказательством работающего процесса.

## Тест-план

- `bash ops/test-fx-factory-release.sh` — изолированные preflight/rollback
  сценарии, включая deleted-inode.
- `bash ops/test-factory-release-systemd.sh` — PASS при доступном root systemd
  fixture; вне systemd допустим только явный SKIP.
- Для живой попытки источник диагностики — полный voyage-log с последним
  `== ...`, строкой `!! ...` и ненулевым exit code при отказе.

## Ограничения

Не меняются production, systemd units, база и код выпуска, кроме тестового
покрытия уже существующего fail-closed gate.
