# «Сделано недавно»: влитое отдельно, провалы честно, даты по-человечески

## Цель и влияние на владельца

Владелец на «Обзоре» должен сразу видеть действительно влитые работы, не теряя их
из-за свежих провалов, и отдельно понимать, какие работы остановились. Успешная
работа получает понятную дату и подтверждение влития; провал — этап и доступную
причину, без ложного знака «готово». Пустые или повреждённые даты не должны
превращаться в обрезанный ISO-текст.

## Технический подход и реальные файлы

В `pilot/pilot.py` сохранить источником факта влития delivery receipt и текущую
фильтрацию служебных работ, но собирать результат в две группы: `merged` для
подтверждённых слияний и `failed` для `failed`/`cancelled`. Каждая группа
дедуплицируется по названию и получает независимый лимит (по умолчанию пять),
поэтому провалы не вытесняют влитое. Для каждого провала передавать отдельные
поля `stage` и `reason`; `reason` брать из результата последней попытки, а при
его отсутствии оставлять честное «причина не указана». Успешные этапы без
receipt не считать влитыми. Старые уведомления сохранять только как аудит.

В `pilot/test_pilot.py` добавить контрактный тест раздельных групп и лимитов:
четыре недавних слияния должны остаться при пяти более свежих провалах; проверить
этап, причину, `cancelled`, дедупликацию и отсутствие receipt у неподтверждённого
успеха. Обязательная команда должна запускать именно этот новый контракт.

В `web/src/Overview.tsx` расширить снимок до групп `merged`/`failed`, добавить
тестируемый `formatRecentDate(value, now)` с локальным временем: «сегодня HH:MM»,
«вчера HH:MM», для старых записей — локальная календарная дата и время.
Невалидная и пустая дата должны давать «дата неизвестна». Отрисовать две
семантически отдельные секции; у провала показать этап и причину, у влитого —
«Влито в main». Машинные статусы и ID владельцу не показывать.

В `web/src/Overview.test.ts` закрепить сегодня, вчера, старую, неверную и пустую
дату через фиксированный `now`, раздельные секции и лимиты, видимые этап и
причину, отсутствие ISO-фрагментов. Подпись очереди заменить на человеческую:
«очередь обычно не длиннее N продуктовых работ» и «данных нет», без «замер» и
`p90`.

## Последовательный план

1. Разделить серверные выборку, дедупликацию и лимиты влитых работ и провалов,
   не меняя источник доказательства слияния.
2. Вернуть для провала этап и причину с безопасным fallback; обновить серверные
   тесты для receipt, пяти провалов и четырёх влитых работ.
3. Добавить локальный форматтер дат с инъекцией текущего времени и устойчивостью
   к пустому и невалидному входу.
4. Разнести отображение на две группы, убрать ISO-срез и обновить подписи
   метрики очереди.
5. Добавить UI-регрессии и выполнить целевые серверные и UI-проверки.

## Критерии приёмки

- После появления delivery receipt слияние попадает в следующий снимок dashboard.
- Пять более свежих провалов не скрывают четыре недавних подтверждённых слияния.
- Влитое и провалы находятся в разных группах с независимыми лимитами.
- Каждый провал показывает этап и доступную причину; неподтверждённый успех не
  получает статус влитого.
- Дата отображается как «сегодня HH:MM», «вчера HH:MM» или понятная старая дата;
  пустая и неверная даты дают «дата неизвестна».
- В блоке нет ISO-фрагментов вида `08-10T12:`, машинных статусов и голых ID.
- Тексты метрик не содержат «замер» и `p90`; при отсутствии границы очереди
  отображается «данных нет».

## Тест-план

- `python3 -m unittest -v pilot.test_pilot.RecentDoneTest.test_separates_merged_and_failed_with_independent_limits`
  — receipt, раздельные группы, лимиты, провалы и причины.
- `npm --prefix web install` — установить зафиксированные UI-зависимости.
- `npm --prefix web test -- --run src/Overview.test.ts` — группы, даты, подписи и
  отсутствие ISO/`p90`.
- `npm --prefix web exec tsc -- -p tsconfig.app.json --noEmit` — типы UI.
- `python3 -m unittest -v pilot.test_pilot.RecentDoneTest` — все серверные
  регрессии области.
- `git diff --check` — чистота правок.

## Риски и решения

- Часовой пояс Pilot и браузера может отличаться: относительные даты вычислять
  только на клиенте, тесты фиксировать через `now`.
- У попытки может не быть текста ошибки: показывать «причина не указана», не
  выдумывая причину по HTTP-коду или названию задачи.
- Старый формат `recent_done` может быть в кеше: UI трактует старый массив как
  пустой, не смешивая старый общий лимит с новыми независимыми лимитами.
- Получение деталей всех задач дорого: сначала выбрать максимум пять элементов
  каждой группы и лишь затем запрашивать детали выбранных попыток.
- Изменение метрики касается только подписи; расчёт и delivery state machine
  остаются вне области.
