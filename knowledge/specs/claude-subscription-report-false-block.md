# Спецификация: отчёт патруля не блокирует подписку Claude

## Цель и влияние на владельца

Свободный текст успешного отчёта, в том числе отчёта патруля со словами
`rate limit`, `quota exceeded` или `usage limit`, не должен переводить всю
подписку Claude в состояние `exhausted`. Владелец не теряет всех Claude-worker
из-за того, что агент описал чужой сбой, процитировал задачу или перечислил
маркеры лимита. Настоящая терминальная ошибка провайдера по-прежнему ставит
временный блок и направляет новые работы на живую подписку.

UI, HTTP-контракты, формат `pilot/limits.json`, пороги расхода и ручной рубильник
не меняются.

## Технический подход и реальные файлы

Дефект находится в `pilot/pilot.py:detect_limits()`. Сейчас функция принимает
`succeeded`, `failed` и `cancelled`, соединяет `attempt.error` со свободным
`attempt.result` двух последних попыток и ищет `LIMIT_SIGNS` по общей строке.
Из-за этого успешный Claude-патруль с такими словами в отчёте вызывает
`note_limit()`; вычисляемый `err_only` не определяет решение, а при отсутствующем
или устаревшем `provider_limits.json` существующая процентная защита не помогает.

Источник автоматического блока следует сузить до последней попытки неуспешной
задачи и её непустого `error`. `result` остаётся пользовательским отчётом и не
участвует ни в классификации, ни в извлечении `resets_at`. Это согласовано с
`internal/worker/supervisor.go`: терминальное событие ошибки Claude формирует
ошибку попытки, а `internal/worker/attempt_lifecycle.go` сохраняет её отдельно
от результата. Существующие `INFRA_SIGNS`, `LIMIT_SIGNS`, `RESET_AT` и
`note_limit()` продолжают применяться к доверенному `error`.

Реальные файлы следующего этапа:

- `pilot/pilot.py` — сузить вход `detect_limits()` до последней failed-попытки
  и её поля `error`;
- `pilot/test_pilot.py` — добавить изолированные регрессии классификации;
- `knowledge/cards/CARD-0173-claude-subscription-report-false-block.md` — вести
  состояние и доказательства этой работы.

## Последовательный план

1. Добавить тест успешного Claude-патруля: `result` содержит несколько точных
   маркеров `LIMIT_SIGNS`, `error` пуст, реального снимка процентов нет;
   `note_limit()` не вызывается.
2. Добавить отрицательные варианты для failed/cancelled задачи с маркерами
   только в `result` и для завершённой успешным повтором задачи, у которой
   маркер остался в предыдущей попытке.
3. Добавить положительный вариант: последняя failed-попытка Claude содержит
   лимит и время сброса в `error`; вызывается `note_limit(conf, "claude", ...)`
   с извлечённым `resets_at`.
4. Изменить `detect_limits()` без новых хранилищ, API и специальных исключений
   по названию патруля; запустить целевой класс тестов.
5. Обновить карточку полным SHA нового implementation commit и результатом
   обязательной команды.

## Критерии приёмки

- Успешная задача Claude не блокирует подписку независимо от текста результата
  и наличия свежего снимка процентов.
- Failed или cancelled задача с маркерами только в `result` не вызывает
  `note_limit()`; отчёт агента не считается доказательством провайдерского сбоя.
- Предыдущая попытка с лимитом не создаёт блок после более новой успешной
  попытки той же задачи.
- Последняя failed-попытка с `LIMIT_SIGNS` в `error` блокирует соответствующий
  провайдер и передаёт найденное `RESET_AT` в существующий `note_limit()`.
- Ошибки, совпавшие с `INFRA_SIGNS`, не считаются исчерпанием подписки.
- Ручное отключение, блок по живому счётчику в `provider_limits_tick()`, формат
  `limits.json` и маршрутизация worker остаются без изменений.
- Тесты полностью изолированы от сети, реальных CLI, подписок и
  `/opt/factory-data`.

- В тесте замокать `api`, `note_limit` и чтение `PROVIDER_LIMITS_PATH`; проверить

## Риски и решения

- **Потеря настоящего result-only лимита.** Worker уже преобразует терминальный
  Claude error event в `attempt.error`, а ошибки запуска Codex попадают туда же.
  Регрессия закрепляет этот контракт; если появится runtime без структурированной
  ошибки, его адаптер должен заполнить `error`, а не возвращать эвристику по
  произвольному отчёту.
- **Старый лимит во второй с конца попытке.** Анализировать только последнюю
  попытку: новый успешный результат является более свежим фактом и не должен
  повторно включать глобальный блок.
- **Слишком узкое исключение только для патруля.** Не распознавать патруль по
  title/context: любой агент может законно обсуждать лимиты в результате.
- **Ослабление других защит.** Не менять `INFRA_SIGNS`, процентные стоп-краны,
  `limit_active()` или `manual_off`; задача меняет только происхождение
  текстового доказательства.
