# План закрывает карточки завершённых работ

## Цель и влияние на пользователя

После успешного окончания всей цепочки `[auto]` связанная карточка Плана должна
сама перейти в `done`. Владелец видит актуальный открытый План, а уже выполненная
работа не может снова попасть в автоподбор только из-за устаревшего состояния
карточки.

## Технический подход

В `pilot/pilot.py` добавить небольшую сверку карточек со снимком задач. Перед
выбором верхней `planned`-карточки она рассматривает только карточки со
сохранённым `task_id`, находит начало именно этого прогона и проверяет задачи с
тем же базовым заголовком не старше связанной задачи. Карточка становится
`done`, только если последний настроенный этап завершился успешно и его
содержательный итог подтверждён через существующий `final_ok(..., strict=True)`.

Сверка охватывает состояния `in_work` и `planned`: второе важно для карточки,
которую после запуска ошибочно вернули в План. Обновление выполняется до
автоподбора в том же цикле, поэтому только что закрытая карточка уже не является
кандидатом на новый запуск. Карточки без `task_id`, незавершённые, упавшие,
отменённые и ожидающие решения владельца не меняются. Формат `ideas.json`, HTTP
API и экран `intake/plan.py` не меняются: используется существующее состояние
`done`, уже скрытое из вкладки открытых карточек.

Затрагиваются `pilot/pilot.py` и целевые проверки в `pilot/test_pilot.py`.

## План реализации

1. Выделить функцию сверки связанных карточек с задачами текущего снимка.
2. Ограничить завершение последним этапом, строгим положительным вердиктом и
   временной границей связанного `task_id`.
3. Вызвать сверку перед автоподбором, чтобы очищенная карточка не стартовала в
   том же цикле повторно.
4. Добавить регрессионные тесты успешного закрытия и защитных случаев.

## Критерии приёмки

1. Карточка `in_work` со связанным прогоном, успешно прошедшим финальный этап,
   переходит в `done`.
2. Такая же карточка в состоянии `planned` сначала переходит в `done` и не
   передаётся в `create_task` повторно.
3. Успех промежуточного этапа, финальный этап без положительного вердикта,
   падение/отмена и открытый вопрос владельцу не закрывают карточку.
4. Старый успешный прогон с тем же названием, созданный до связанного `task_id`,
   не закрывает текущую карточку.
5. Карточка без `task_id` не меняется: неоднозначное совпадение только по тексту
   не считается доказательством выполненной работы.

## План тестирования

В `pilot/test_pilot.py` добавить `PlanCardCleanupTest` с изолированными данными
задач и подменой `ideas_all`, `set_idea`, `final_ok` и создания задачи. Проверки
должны доказать закрытие успешного финала, отсутствие повторного старта и
сохранение карточки во всех неоднозначных/незавершённых случаях.

Обязательная команда: `python3 -m unittest pilot.test_pilot.PlanCardCleanupTest`.
После неё должен проходить весь модуль: `python3 -m unittest pilot.test_pilot`.

## Риски и решения

- Зависимость: автоподбор из `CARD-0034-plan-priority-autostart.md` ещё не входит
  в текущий `origin/main`; реализацию этой спецификации нужно вести поверх него
  либо после его слияния. Дублировать автоподбор в этой работе не следует.
- Решение: не закрывать legacy-карточки без `task_id`; автоматическая догадка по
  одинаковому названию способна скрыть намеренный новый прогон.
- Решение: использовать строгий финальный вердикт, а не один лишь `succeeded`,
  поскольку успешное выполнение агента ещё не означает принятую поставку.
- Риск: API отдаёт ограниченный снимок задач; если связанная или финальная задача
  выпала из него, очистка безопасно откладывается до появления достаточных
  данных. Расширение пагинации — отдельная работа.
- Вне области: удаление записей из `ideas.json`, изменение вкладок Плана,
  автоматическое закрытие проваленных либо вручную созданных legacy-карточек.
