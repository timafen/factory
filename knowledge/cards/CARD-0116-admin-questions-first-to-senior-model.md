### 2026-08-13 — Specification

Проверены `pilot/pilot.py`, `ops/fx`, `pilot/test_pilot.py` и HTTP API вопросов.
Сейчас `route_question()` передаёт вопрос в `orchestrator_answer()`, но модель
может только вернуть текст, а `brain()` не имеет исполнимого ограниченного
admin-канала. `ops/fx` уже является подходящим посредником: запускается через
`sudo -n`, сверяет включённые владельцем grants и имеет жёсткий список
операций.

Определена реализация с типизированным admin-намерением, консервативной
валидацией argv и аудитом результата. Для разрешённого staging-действия
старшая модель выполняет его сама; к владельцу попадают только операции за
установленной границей либо отказ посредника. UI и `ops/fx` на стадии
Specification не меняются.

Критерий готовности привязан к отдельной регрессии
`AdminQuestionRoutingTests.test_allowed_staging_health_is_resolved_by_orchestrator_before_owner`:
она должна подтвердить точный argv `fx`, единственное выполнение и отсутствие
owner-only вопроса после успешного ответа старшей модели.

Номер и путь карточки проверены по свежему `origin/main` и опубликованным
веткам: `CARD-0116` отсутствует в дереве main и среди имён опубликованных
веток.
