## LOG

### 2026-08-14 — Specification

Фактический код уже умеет отличать Factory Pipeline Patrol по durable
Automation/schedule-признакам, но список Tasks не передаёт этот класс экрану
«Работа». Automation occurrence, в свою очередь, содержит состояние и
diagnostic, но не сохранённые `attempt.result`/`attempt.error`, хотя pilot уже
читает оттуда находки.

Определён единый контракт: control plane добавляет класc к списочной Task и
последнюю попытку к occurrence; Work скрывает только класс `patrol`, а
Automation показывает состояние, явные строки `НАХОДКА:`, полный итог или
нейтральное отсутствие результата. Обычные Automation и пользовательские
работы остаются видимыми; простой success больше не называется пройденной
проверкой.

## Критерий завершения карточки

Целевые Go-тесты доказывают устойчивую классификацию и проекцию последней
попытки, а UI-тесты одновременно покрывают успешный, неуспешный и пустой
патрульный запуск, отсутствие патрулей в Work и сохранение обычных работ.

## Проверяемая сдача Specification

Спецификация обязана перечислять каждый будущий файл реализации отдельной
строкой `ГОТОВО-КОГДА: файл ...`. Обязательная команда после реализации:
`cd web && npm test -- --run src/Work.test.ts src/Automations.test.tsx`;
она должна завершаться кодом 0 и проверять именно перенос патрулей и их
находок, а не только типизацию или сборку.
