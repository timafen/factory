## Почему это дубликат

Кандидат CARD-0122 уже содержит durable снимки «до/после», ежедневную сборку
PDF, календарные метрики, list/download API, browser isolation и экран
`/reports`. Параллельная реализация создала бы второй источник отчётов и
расходящиеся правила capture, поэтому продолжение разрешено только через Review
и Verify существующей ветки.

## Зафиксированная проверочная база

- Свежая база `main`: `73f4edce272cb113607540412425d842158e2b81`.
- Кандидат CARD-0122: `a4c55bdee4deb554f5f7e35756045a43f0584836`.
- Сравнение: только трёхточечный diff между указанными SHA, полученными из
  отдельных remote refs.
- Текущее состояние кандидата: не PASS; новый тест ошибки БД падает при
  повторном закрытии хранилища в cleanup.

## Следующее действие

В канонической ветке CARD-0122 сделать cleanup теста ошибки БД идемпотентным,
повторить его пять раз, затем провести Review полного diff. Только Review PASS
разрешает однократный полный Verify и последующее слияние. Эта карточка не
переходит в Implement + Test.
